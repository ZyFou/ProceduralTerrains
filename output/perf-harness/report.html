Memory

What the caches cost in VRAM

Most of the GPU time saved comes from evaluating the procedural field once into textures instead of per pixel per frame. That trade is visible in dedicated GPU memory, so every cache is sized to what it serves and freed when it is not needed.

Level of detail

Smooth LOD transitions

Tile mode uses CDLOD distance-band geomorphing: odd vertices slide onto the next coarser grid before a chunk swaps, and merged far nodes fold only where every vertex already has the coarse shape, so a swap changes nothing on screen. Infinite World and Planet chunks keep their LOD decisions but animate each change over 0.4 s. The pop test flies a camera path and renders every frame twice at the same pose, once with LOD frozen and once re-selected; the worst single-frame difference is what a viewer sees as a pop. With temporal morphing a change is spread over many small frames, so the count of frames that differ at all can rise while each step stays far below a visible pop.

Changes

Iteration log

it1−7.7%17.63 ms

Branch-friendly sampling (exact)

Implicit-derivative texture lookups inside heightAt made ANGLE/FXC flatten every surrounding branch, so disabled features and the bake/live branch ran for every pixel. All non-mipmapped data-texture lookups now use explicit LOD 0 (bit-identical), and cache fallbacks use statement branches instead of ?:.

  • terrainGLSL.js / TerrainMaterial.js / waterShaderGLSL.js / RealisticWaterMaterial.js: data textures (bake, paint, sculpt, spline, erosion, destruction, imports, occupancy, clipmap, scene depth/colour, planar reflection) sampled with textureLod(..., 0.0)
  • TerrainDetailMaterial.js, SurfaceArrayGLSL.js: page/paint arrays sampled with textureLod
  • INFINITE_FIELD_CACHE_GLSL + waterTerrainHeightAt: real if/else so the procedural fallback is skipped when the cache covers the pixel
it2−17%14.71 ms

Live/baked hybrid height field (Tile mode)

Tile terrain + water fragments evaluated the full procedural height field 3x per pixel (~150 value-noise calls). A generation-, layout- and authoring-matched bake (normal xz, curvature, height) now replaces it wherever a pixel spans about one bake texel; the exact live field is kept near the camera. Realistic water's 6 low-pass height taps run in a uniform-bound loop (one inlined height graph instead of six).

  • TerrainHeightBaker.js: packed RGBA16F (normal.x, normal.z, curvature, height); single inlined heightAt via uniform-bound sample loop; back buffers released after each bake (VRAM)
  • terrainGLSL.js: terrainBakeBlendWeight / terrainBakeWeight / bakedNormalFromTexel helpers; uBakeTexelWorld, uPixelWorldPerDist, uBakeBlend uniforms
  • TerrainMaterial.js: studio fragment blends live and baked height/normal/curvature by pixel footprint; infinite far-normal derivative hoisted out of the branch
  • waterShaderGLSL.js / RealisticWaterMaterial.js: hybrid shoreline height, baked low-pass taps, looped smoothing/slope taps
  • Engine.js: bake enabled for procedural Tile projects; authoring tools (paint, sculpt, texture paint, splines, explode) keep the live field while active; bake key includes authoring revisions; per-render pixel footprint from scene.onBeforeRender (orthographic passes stay live); bake program no longer gates the boot compile; 2048 bake on medium/high tiers
it3−2.1%14.40 ms

Loop-unroll guard on every FBM loop + VRAM release

Octave loops had compile-time bounds, so ANGLE/FXC fully unrolled every FBM at every call site. Bounds now add a never-set uniform (GL guarantees 0): identical trip counts, real loops. Smaller D3D programs compile ~1/3 faster and run faster. The studio bake's render targets are freed when Tile mode is left.

  • terrainGLSL.js / planetGLSL.js / noise/noiseTypes.js: `i < OCTAVES + uLoopGuard` (and the 4-octave helpers)
  • TerrainHeightBaker.releaseTargets + Engine._releaseStudioHeightCache on Infinite/Planet entry
  • Harness: median-based score, idle detection per mode
it4−6.7%13.44 ms

Planet: real bake branch + single-copy height sampling

The planet terrain fragment sampled its baked cubemap with implicit derivatives, so FXC flattened the branch and the 3D height field ran 3x per pixel even with the bake published; the three samples were also inlined as three full copies (46.8 s compile). Cubemap lookups are now explicit-LOD and the samples share one uniform-bound loop (terrain fragment, minimal fragment, cubemap baker); planet water uses a statement branch.

  • PlanetMaterial.js: textureLod(uPlanetHeightTex, ...), single-copy sample loop, water if/else
  • PlanetHeightBaker.js: single-copy sample loop
  • Harness: best-of-2 static measurements (paths measured once to keep streaming hitches visible)
it5−3.9%12.92 ms

Geomorphing (smooth LOD transitions) — distance bands (Tile)

CDLOD-style morph in the terrain vertex shader: odd grid vertices slide onto the next-coarser grid inside a band placed half a chunk diagonal inside each LOD switch, so swaps are invisible in both directions. Merge-layer folds now wait until chunks are fully LOD3-shaped (the baseline folded LOD0/1 chunks straight to 8-quad density, an 8x pop). With pops gone, Tile LOD bands were retuned to a ~3 px screen-space target.

  • LodMorph.js: planMorphBands / publishMorphUniforms (+ unit tests)
  • ChunkGeometry.js: opt-in aMorph attribute on the shared per-LOD grids
  • TerrainMaterial.js: terrainMorphedGrid() in the vertex shader; uLodMorphStart/End/uLodGridSegments
  • TerrainBoard.js: morph bands, exact node distance, lossless fold gating, BASE_DISTANCE_BANDS [8,15,24] -> [5.2,9.75,15.6]
  • Harness: A/B LOD-pop metric (frozen vs re-selected LOD at the same pose)
it5b−0.7%12.83 ms

Temporal geomorph for Planet and Infinite World

Planet chunks are ~4000 units across, so distance bands would sit in front of the camera and soften visible detail (first attempt: MAE 2.96% on the near view, rejected). Planet and Infinite keep their original LOD decisions and instead animate every LOD change per chunk (0.4 s morph, per-instance factor); settled geometry is bit-identical to before. Planet folds wait until their chunks have morphed to LOD3; freshly created chunks snap to their level.

  • LodMorph.js: stepTemporalLod state machine (+ unit tests)
  • PlanetWorld.js / PlanetMaterial.js: per-instance aMorphK, fold readiness, fresh-chunk snap
  • InfiniteWorld.js / InfiniteTerrainBatches.js / TerrainMaterial.js: per-instance aMorphK for instanced chunks
it6−12%11.33 ms

Startup: shader cache, no first-use stall, smaller programs

Measured that Chrome only writes WebGL programs to its disk cache when a link is resolved synchronously, yet async links read the cache: every launch recompiled the terrain (~10 s). Boots now stay asynchronous by default and, after a launch that missed the cache with a safely short compile, the next boot links synchronously once to fill it — later launches are ready in ~0.9 s. Found and removed an 8.5-11 s main-thread freeze: the minimap rendered the scene before its programs linked, so three.js blocked in its first-use link check. Caustic Worley loops, cellular noise and fbm3 got the unroll guard (terrain fragment cold compile 8.2 -> 6.7 s).

  • EngineProxy.js: adaptive boot shader-link policy (record in localStorage, pending-sync fallback) + unit test
  • Engine.js: _resolveProgramLinks / _cacheableBootCompile, presented first-launch message before a cache-filling boot, onBootShaderStats
  • Minimap.js / Engine.js: scene renders gated on linked programs; worker frame packets reuse the base image and read back asynchronously; canvas-less minimap no longer forces a render every tick
  • TerrainMaterial.js / noisePrimsGLSL.js / biomeGLSL.js / planetGLSL.js: guarded caustic, cellular and fbm3 loops
it7−2.2%11.08 ms

CPU hitch removal: resumable prop sectors, cloud loop guard, planet bake race

Props sector builds (up to ~30 ms each) are now resumable inside the per-frame budget, so the orbit-zoom path CPU p95 dropped from 11.6 to 6.8 ms in studio-full. Cloud volume/slab loops got the unroll guard and non-mipmapped occupancy lookups use textureLod (no branch flattening). Fixed a pre-existing race exposed by the faster compiles: entering planet mode ran the warm-up and an octave rebuild that each prepared the same height-bake program, and the second invalidated the first, so the transition failed with "Planet shader compilation did not complete". Same-program preparations are now shared.

  • ProceduralPropsManager.js: _beginFlatSector/_stepFlatSector resumable sector builds (deadline checked every 32 candidates, identical output)
  • cloudGLSL.js / CloudSlabShader.js / CloudVolumeShader.js: guarded loops, textureLod occupancy
  • PlanetHeightBaker.js: shared pending program preparation + tests/PlanetHeightBakerPrepare.test.js
  • Engine.js: planet compile error names the stage that failed
it8−16%9.36 ms

Near-camera height from the bake + zoom-in freeze fix

GPU attribution of the close view showed the per-pixel live noise stack near the camera was ~60% of the frame (17.8 of 28.4 ms, terrain + water). A crossover sweep showed the bilinear bake (height, packed normal, curvature) stays within 0.4% SSIM of the live field down to ~0.3 texels per pixel, so the live/baked crossover moved from 0.75-1.25 to 0.3-0.5 texels per pixel; extreme close-ups still evaluate the live field. Also fixed the user-reported 6-12 s freeze when zooming close: three.js r185 keys programs on HAS_NORMAL and terrain chunk grids have no normal attribute, so every terrain warm-compile on the normal-bearing probe plane built a program the chunks never used; the first close-up frame then compiled the real 75k-char terrain program synchronously (11.8 s on the baseline build, 0 ms now).

  • TerrainMaterial.js / terrainGLSL.js: uBakeBlend 0.3:0.5 (was 0.75:1.25)
  • Engine.js: _warmGeometryFor + normal-less warm probe for terrain/planet chunk materials; regression test in BootShaderCompilation.test.js
  • perf-harness: probe --cold (empty shader cache), experiments zoom-lag, gpu-attribution3, bake-threshold, depth-prepass (rejected: -13% only, vertex pass is cheap but live height dominates)
it9−1.7%9.20 ms

Clouds: no detail noise inside solid cores

Attribution of the clouds + props + realistic-water scene put the volumetric clouds at 6.2 of 9.3 ms in the overview. The detail FBM and the 27-cell Worley erosion only act through the edge mask 4·cov·(1−cov), which is exactly zero in solid cloud cores, yet both were evaluated there. They are now skipped when the mask is zero: pixel-identical output, overview 9.4 -> 8.7 ms GPU. An exact early-out for the base FBM (bounding the remaining octaves) was measured and rejected: the per-octave tests cost more than they saved in the overview.

  • cloudGLSL.js: detail FBM + Worley evaluated only where edge > 0 (studio slab, planet shell and infinite clouds share it)
  • perf-harness: gpu-attribution4, cloud-edge-skip, cloud-ab, verify-vs-run (fresh-boot A/B; in-page shader swaps proved order-dependent)

Planet: instanced merged patches, one material

CPU profiling of the planet orbit view showed three.js uniform refresh dominating the engine side: every folded far patch owned its own material (269 uniforms, 24 uncached array uniforms), so each of ~70 patch draws re-uploaded everything. Patches now render as instanced batches per patch grid size, sharing one material and the same instanced program as the chunk batches (one fewer shader variant). Chunk instance buffers are re-uploaded only when visibility, LOD or morph change. Orbit CPU 2.2 -> 0.6 ms and 73 -> 4 draw calls, frame 4.6 -> 3.0 ms; pixel-identical.

Near-camera bake level (one-level clipmap)

After it8 about 6 ms of the close view was still the live noise stack for pixels nearer than the 2048² board bake resolves. A camera-centred 1024² window at half the board texel size, baked by the same compiled program through a second material with private origin/span uniforms (no new shader), now serves those pixels with the same footprint criterion; the live stack only runs for extreme close-ups. Not done

Remaining opportunities and rejected ideas

  • Volumetric cloudsStill about 5 ms of the clouds + props + realistic water overview on the High preset. Temporal reprojection (marching a quarter of the cloud pixels per frame) is the next AAA step; it was left out because animated clouds under a moving camera can ghost.
  • Terrain shadingWith height and climate cached, the remaining 6–7 ms of a Tile close-up is spread over many shading features; no single cache is left to add.
  • Surface-texture variantsFound during the sampler audit: the Terrain › Surface › Textures shader variants need 17 texture units and fail to link on 16-unit GPUs (ANGLE / Direct3D 11) in the base commit too. Reported as a separate task.
  • Depth pre-pass−1 to −13% depending on the iteration, with small depth-related image changes; three.js already sorts opaque terrain front to back.
  • Deferred terrain shading−41% on the close terrain pass in a prototype, but it needs a second terrain-sized program (compile time) and breaks MSAA edges.
  • Bounded-FBM early exit for cloudsExact, but the per-octave tests cost more than they saved in the overview.
  • Front-to-back sorting of planet patch instancesNo measurable GPU gain and tiny depth-tie differences.
Method

How it was measured

  • Real GPU, deterministic framesHeadless Edge on the machine's GPU (ANGLE D3D11), a fake engine clock, LOD and animation frozen while a view is timed. Re-running a capture reproduces it bit for bit.
  • Serialized frame costEach frame is submitted, then synchronised with a 1-pixel read-back; GPU time comes from EXT_disjoint_timer_query. Every view is timed twice and the better repetition kept.
  • MemoryWindows per-process counters for the renderer and GPU processes, plus dedicated/shared GPU memory, sampled after each scene.
